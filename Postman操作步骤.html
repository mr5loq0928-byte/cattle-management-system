Postman 手把手操作步骤

一次都没用过 Postman 也能跟上。照着做，10 分钟就能发出第一个请求。

开始前确认：已经双击过 启动接口服务.bat，而且那个最小化的「接口服务」黑窗口还开着。
不确定的话，用浏览器打开 http://127.0.0.1:8124/，能看到"接口服务正在运行"就对了。
1
打开 Postman，新建一个「集合」

集合（Collection）就是"文件夹"，用来把同一套接口的请求放在一起，不然一会儿就乱成一锅粥。

  1. 打开 Postman，左边一栏找到 集合（Collections），点它旁边的 + 号，或者点 新建（New）
  2. 选 集合（Collection）
  3. 名字填：接口测试练习，回车保存
2
先发一个最简单的：查牛只列表
  1. 点左边 接口测试练习 集合，右边出现 添加请求（Add a request），点它
  2. 上面那一行，左边下拉框默认是 GET，不用动
  3. 右边地址栏填： 
    http://127.0.0.1:8124/api/cows
  4. 点右边的蓝色按钮 发送（Send）
如果下面出现一大堆 JSON，恭喜，你已经会用了。剩下 90% 的操作都是在这个基础上改。
3
看懂下面那块响应区

点了发送之后，Postman 下半部分会变成这样，四个地方要关注：

位置是什么
正文 → 那块带 1 2 3 行号的内容区
教材、英文版里叫 Pretty（美化）		服务器返回的内容，Postman 已经帮你格式化好了，最好看。写用例时【实际结果】就从这儿抄。
正文 → 左边那个 {} JSON 下拉框
教材、英文版里叫 Raw，你这版没有这个按钮了		决定用什么格式看这段内容（JSON / Text / HTML / XML）。想看原始的一行到底的文本，就把它改成 Text。平时不用动它。
正文 → 右边的 预览 / 可视化
这个练习用不上		预览 = 把返回内容当网页、图片那样看；可视化 = 用脚本把返回数据画成图表。知道有这两个按钮就行。
右上角 200 OKHTTP 状态码。200 成功、400 参数错、401 没登录、404 找不到、500 程序崩了。
旁边的 Time / Size响应时间（毫秒）和返回数据大小。性能相关的问题看这里。
找不到教材里的 Pretty / Raw？那是老版本（英文界面）的名字。你这版 Postman 12.28.6 中文版里：Pretty 就是你默认看到的那块带行号的内容区；Raw 这个按钮被去掉了，想把内容当普通文本看，就在左边的 {} JSON 下拉框里选 Text。做这个练习，默认的视图完全够用。
新手最爱犯的错：只看 Body，不看状态码。有些缺陷恰恰是"Body 说成功，但状态码是 500"。
4
发一个 POST 请求（用户登录）
  1. 再 添加请求，名字改成 用户登录
  2. 左边下拉框从 GET 换成 POST
  3. 地址填： 
    http://127.0.0.1:8124/api/login
  4. 点地址栏下面的 正文（Body） 标签
  5. 选 raw，最右边那个下拉框从 Text 改成 JSON
  6. 在下面的大框里粘这段： 
    {
  "username": "admin",
  "password": "123456"
}
  7. 点 发送（Send）
为什么必须选 JSON？ Postman 会自动帮你加上请求头 Content-Type: application/json。如果不选，服务器就不知道你发的是什么格式，可能直接报错。
顺便看一眼：选完 JSON 之后，切到 请求头（Headers） 标签，你会看到 Postman 悄悄加的那一行。
5
把 token 记下来

登录成功的返回里有一个 token，长得像 tk_admin_1789882355671。后面新增、删除牛只都要用它，先复制出来放到记事本里。

注意：每次登录 token 后面那串数字都不一样，这是正常的。你复制哪一次的都行。
6
带 token 发新增请求
  1. 再 添加请求，名字叫 新增牛只
  2. 方法选 POST，地址填 http://127.0.0.1:8124/api/cows
  3. 切到 请求头（Headers） 标签，在表格里加一行：
    KeyValue
    Authorization刚才复制的 token，例如 tk_admin_1789882355671
  4. 切回 正文（Body） → raw → JSON，粘上： 
    {
  "ear_tag": "A0021",
  "breed": "安格斯",
  "gender": "公",
  "in_date": "2026-09-20",
  "weight": 520.5
}
  5. 点 发送。成功的话你会看到 201 Created，返回里带一个 id（比如 11）
把这个 id 记下来。一会儿删它、查它都要用。这就是"造测试数据"。
如果你把 Authorization 那一行去掉再发一次，会看到 401 —— 这是对的，说明接口在检查登录。
那删除接口呢？记得也试试不带 token 删一次。
7
查询参数用 Params 标签写（别手敲 URL）

要测 ?page=2&size=5&breed=荷斯坦 这种，别在地址栏里手打，用 参数（Params） 标签，一个格子填一个：

KeyValue
page2
size5
breed荷斯坦

你一边填，上面地址栏会自动变成 .../api/cows?page=2&size=5&breed=荷斯坦。中文会被自动转码成 %E8%8D%B7…，这是正常的，不要去改它。

勾掉某一行前面的小勾勾，这个参数就临时不生效 —— 用这个办法可以快速对比"带参数"和"不带参数"的返回差异，很好用。
8
把请求保存下来，然后复制改参数
  1. 每调好一个请求，按 Ctrl + S 保存到 接口测试练习 集合里，不然关了就没了
  2. 要测同一个接口的另一组参数：右键这个请求 → 复制（Duplicate），改个名字和参数就行
  3. 想批量重命名 / 整理，在左边集合里拖动就行
为什么建议每条用例存一个请求？ 因为你写测试用例时要填"实际结果"，存下来随时能再跑一次对照，也能截图当证据。这是真实工作的习惯。
9
DELETE 请求怎么发

方法下拉框选 DELETE，地址填 http://127.0.0.1:8124/api/cows/11（11 就是刚才新增那头的 id），Headers 里带上 Authorization，点发送。

删完别急着走：再发一次 GET /api/cows/11，确认它真的没了（应该返回 404）。这一步叫"数据一致性验证"，是测试的基本功。

出问题了怎么排查

你看到的原因和处理
发送后卡住，或提示 Error: connect ECONNREFUSED接口服务没启动。双击 启动接口服务.bat，等 3 秒再发。
404 + 接口不存在URL 路径写错了，检查是不是漏了 /api，或者多打了一个斜杠。
500 + 一堆英文报错程序崩了。这本身就是一个缺陷，把请求参数和返回内容一起记下来，写进缺陷清单。
400 + 请求体不是合法的 JSONBody 里的 JSON 写错了，通常是少了逗号、少了大括号，或者 Body 那栏的格式没选 JSON。
返回的中文是乱码Postman 很少出现。真的遇到就切到 Body → Raw 看一下原始内容。

动手顺序建议

  1. 先按上面 1~5 步发一次成功的请求，建立手感
  2. 再打开 练习题.html 和 接口文档.html，开始写用例
  3. 每写完一条用例，就在 Postman 里跑一次，把实际结果填回去
  4. 跑的时候觉得"这不对啊"，别放过它 —— 那就是缺陷
