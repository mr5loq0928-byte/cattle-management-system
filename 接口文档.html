牛只管理系统 · 接口文档

这是「被测系统」的接口说明书。你要照着它写测试用例，再用 Postman 一条条去验证。文档写的是"应该怎样"，实际接口可能不是这样 —— 对不上的地方就是缺陷。

先做三件事：
  1. 双击 启动接口服务.bat —— 服务跑起来后浏览器会自动打开本文件
  2. 确认服务活着：浏览器访问 http://127.0.0.1:8124/ 能看到"接口服务正在运行"
  3. 打开 Postman，对着下面的接口一个个发请求

一、通用约定

项目说明
服务地址http://127.0.0.1:8124
请求格式JSON，请求头要带 Content-Type: application/json
编码UTF-8
鉴权方式登录后拿到 token，放在请求头 Authorization: 你的token
数据存储内存里，重启服务就恢复成初始的 10 头牛

响应统一结构

{
  "code": 0,          // 0 = 成功，非 0 = 失败
  "msg": "ok",        // 提示信息
  "data": { }         // 具体数据，失败时通常是 null
}

错误码对照表

codeHTTP 状态码含义
0200 / 201成功
1001200用户名或密码错误
1002400请求参数不合法（含请求体不是合法 JSON）
1004404牛只不存在
1404404接口路径不存在
2001401未登录或 token 无效
5000500服务器内部错误
注意看这条规则：参数不合法时应该返回 400 + code 1002，而不是 500。
500 是"程序崩了"，属于严重问题；参数写错是用户能犯的错，应该给友好提示。

二、业务规则

  • 耳标号必须唯一 —— 系统里不能有两头牛用同一个耳标号。
  • 必填字段：ear_tag、breed、gender、in_date、weight。缺任何一个都应该返回 400 + code 1002。
  • 选填字段：state，不传时默认是 正常。
  • 性别只能是 公 或 母；状态只能是 正常 / 出栏 / 淘汰。
  • 需要登录才能调用的接口：新增牛只、删除牛只。没带 token 必须返回 401 + code 2001。
  • 不需要登录的：登录接口本身、牛只列表、牛只详情。
  • 返回的用户信息中不允许包含密码（安全要求，明文密码属于严重问题）。
接口清单

接口 1 · 用户登录

POST/api/login不需要 token

请求体参数

参数名类型必填说明
username字符串是用户名，系统里有 admin 和 tester 两个账号
password字符串是密码，两个账号的密码都是 123456

请求示例

POST http://127.0.0.1:8124/api/login
Content-Type: application/json

{
  "username": "admin",
  "password": "123456"
}

成功响应（200）

{
  "code": 0,
  "msg": "登录成功",
  "data": {
    "token": "tk_admin_1789882355671",
    "userId": 1,
    "username": "admin",
    "role": "管理员"
  }
}
看清楚：返回的 data 里只应该有 token、userId、username、role 四个字段。不应该有 password。

失败响应（密码错误 / 用户名不存在）

{
  "code": 1001,
  "msg": "用户名或密码错误",
  "data": null
}
要测的点：正确密码、错误密码、用户名不存在、用户名为空、密码为空、多传一个没用的字段、大小写（Admin vs admin）……
别忘了：密码错误和用户名不存在，返回的提示应该一样（不能告诉对方"用户名对了密码错了"，那是安全漏洞）。

接口 2 · 牛只列表（分页 + 筛选）

GET/api/cows不需要 token

URL 查询参数（都是选填）

参数名类型默认值说明
page整数1第几页，从 1 开始
size整数5每页显示几条
breed字符串空按品种筛选，如 荷斯坦
state字符串空按状态筛选，如 淘汰

请求示例

GET http://127.0.0.1:8124/api/cows?page=1&size=5
GET http://127.0.0.1:8124/api/cows?page=2&size=5
GET http://127.0.0.1:8124/api/cows?breed=荷斯坦

成功响应（200）

{
  "code": 0,
  "msg": "ok",
  "data": {
    "page": 1,
    "size": 5,
    "total": 10,
    "list": [ { "id": 1, "ear_tag": "A0001", ... } ]
  }
}
三个关键约定，测的时候一条条对：
1. page 是第几页就返回第几页的数据 —— page=2 不能再给第一页的牛。
2. size 是几条就返回几条。
3. total 是符合条件的总条数，不是本页条数。比如库里一共 10 头牛，按品种筛出 3 头，那 total 应该是 3。
（初始数据：一共 10 头牛。荷斯坦 3 头、西门塔尔 3 头、夏洛莱 2 头、鲁西黄牛 2 头；淘汰状态 1 头、出栏状态 2 头。）

接口 3 · 牛只详情

GET/api/cows/{id}不需要 token

路径参数

参数名类型必填说明
id整数是牛只编号，如 3

成功响应（200）

{
  "code": 0,
  "msg": "ok",
  "data": {
    "id": 3,
    "ear_tag": "A0003",
    "breed": "西门塔尔",
    "gender": "公",
    "in_date": "2023-11-20",
    "weight": 610.8,
    "state": "出栏"
  }
}

失败响应（404）

{
  "code": 1004,
  "msg": "牛只不存在",
  "data": null
}
要测的点：存在的 id、不存在的 id（比如 999）、id 传 0、id 传负数、id 传字母 abc、id 不传（变成 /api/cows/）。
每种情况的状态码和 code 都要和文档对上。

接口 4 · 新增牛只

POST/api/cows需要 token

请求头

名称值
Content-Typeapplication/json
Authorization登录接口返回的 token，例如 tk_admin_1789882355671

请求体参数

参数名类型必填说明
ear_tag字符串是耳标号，不能和已有的重复
breed字符串是品种
gender字符串是公 / 母
in_date字符串是入栏日期，格式 YYYY-MM-DD
weight数字是体重（公斤）
state字符串否不传默认 正常

请求示例

POST http://127.0.0.1:8124/api/cows
Content-Type: application/json
Authorization: tk_admin_1789882355671

{
  "ear_tag": "A0021",
  "breed": "安格斯",
  "gender": "公",
  "in_date": "2026-09-20",
  "weight": 520.5
}

成功响应（201）

{
  "code": 0,
  "msg": "新增成功",
  "data": {
    "id": 11,
    "ear_tag": "A0021",
    "breed": "安格斯",
    "gender": "公",
    "in_date": "2026-09-20",
    "weight": 520.5,
    "state": "正常"
  }
}

失败响应

// 没带 token（401）
{ "code": 2001, "msg": "未登录或 token 无效", "data": null }

// 缺必填参数 / 参数不合法（400）
{ "code": 1002, "msg": "参数不合法：ear_tag 不能为空", "data": null }
要测的点（这是本套练习的重点）：
1. 正常新增一头牛，新增完再用 GET /api/cows/{id} 查一下，确认真的存进去了；
2. 五个必填字段逐个不传，看返回什么；
3. 用已经存在的耳标号（比如 A0001）再新增一次，看会不会被拦住；
4. 体重传负数 / 0 / 超大值 / 文字；日期传 2026-13-45 这种不存在的日期；性别传 未知；
5. 不带 token、带一个假 token。

接口 5 · 删除牛只

DELETE/api/cows/{id}需要 token

路径参数

参数名类型必填说明
id整数是要删除的牛只编号

请求示例

DELETE http://127.0.0.1:8124/api/cows/11
Authorization: tk_admin_1789882355671

成功响应（200）

{
  "code": 0,
  "msg": "删除成功",
  "data": { "id": 11, "ear_tag": "A0021", ... }
}

失败响应

// 没带 token（401）
{ "code": 2001, "msg": "未登录或 token 无效", "data": null }

// 牛不存在（404）
{ "code": 1004, "msg": "牛只不存在", "data": null }
要测的点：先新增一头牛拿到它的 id，再删掉它，然后再查一次确认真的没了；
删一个不存在的 id；不登录直接删（这条是重点，一定要试）；删一个已经删过的 id（重复删除）。

接口 6 · 练习辅助接口（不算测试对象）

POST/api/_reset

把数据恢复成最初的 10 头牛。做增删改练习弄乱了，就调它一下，不用重启服务。

POST http://127.0.0.1:8124/api/_reset
{ "code": 0, "msg": "数据已恢复", "data": { "count": 10 } }
这个接口是给你练习用的，不要去测它。
